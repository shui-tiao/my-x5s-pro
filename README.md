## 协议规格

### 1. 帧格式

```
┌──────┬────────┬────────┬──────┬───────────────┬────────┬────────┐
│ 0x5A │ len_hi │ len_lo │ 0x00 │ TLV payload…  │ crc_hi │ crc_lo │
└──────┴────────┴────────┴──────┴───────────────┴────────┴────────┘
  len = payload.length + 1（16 位大端）
  crc = CRC-16/XMODEM(poly 0x1021, init 0x0000)，覆盖 [0x5A .. payload 末尾]
```

### 2. TLV 编码

```
[tag:1B] [len] [value]
len < 0x80  → 1 字节
len >= 0x80 → 2 字节：0x80 | (len >> 8), len & 0xFF
```

### 3.2 降噪设置命令（已确认，真机可切）

**写入**：`2B 04`，载荷固定 6 字节：

```
2B 04 01 02 <mode> <level>
mode:  00=关闭  01=降噪  02=透传
level: 00=智能  01=轻度  02=中度  03=深度
整帧：5A 00 07 00 2B 04 01 02 <mode> <level> <crc_hi> <crc_lo>

**回读**：`2B 2A 01 00` → 应答 `2B 2A 01 02 <level> <mode>`，
**第一字节是等级、第二字节是模式**（早期实现把顺序弄反，导致 level=0 时被误判成「关闭」，已修正）。

### 3.4 属性通道 `01 39` / `01 3A`（EQ、LDAC、空间环绕声）

**这四项不走 `2B xx`，走的是「属性读写」通道**。`2B 6D/6E`（EQ）、`2B 1A/1B`（LDAC）、
`2B 75/76`（空间）在本机固件 1.1.64.2 上**发出去连 7F 都不回**（静默丢弃），
USFY 实际走的是属性通道。

```
写：01 39 + TLV(1, serviceIndex int32) + TLV(2, propertyIndex int32) + TLV(3, value int32)
    载荷固定 20 字节（官方日志 length=21）
读：01 3A + TLV(1, TLV(2, TLV(3,service) + TLV(4,prop) + [flag,00]))   ← 两层嵌套，flag=0x05
    应答 01 3A 81 14 82 12 03 04 <service> 04 04 <prop> 05 04 <value>
```

**读必须是两层嵌套，写成平铺 TLV 会被 7F 拒绝**——这是排查最久的一个坑。

读：2B 19 应答 01 01 <右> 02 01 <左>   tag1=右耳 tag2=左耳
```

wire 值是固件枚举，**不是参与轮换的模式个数**（初版按「个数」解读是反的）。
全枚举经官方 APP 页面渲染锚定：

| wire 值 | 官方页面渲染      | 实测证据                                                |
| ------ | ----------- | --------------------------------------------------- |
| 1      | 降噪✓ 关闭✓ 透传✗ | 官方取消透传勾选时写 `2B 18 01 01 01 02 01 01`（官方 APP 实测） |
| 2      | 三项全勾（默认）    | 官方勾回任一项即写 2；无效值 7 被钳回 2；用户物理确认三模式轮换                 |
| 3      | 降噪✓ 关闭✗ 透传✓ | 我们写 3,3 后官方页面直接渲染此状态                                |
| 4      | 降噪✗ 关闭✓ 透传✓ | 官方取消降噪勾选时写 `2B 18 01 01 04 02 01 04`（官方 APP 实测） |

**写完就结束，不要发任何后续帧**：`2B 18 03 01 00` 是耳机方向的 ACK（tag3=状态码 0=成功）。
若手机把 ACK 当请求再回一条 `2B 18 03 01 00`，设置会被重置回默认 2
（实测写 3 + 提交帧后回读恒 2,2；去掉提交帧后写 1/2/3/4 回读立即跟随）。

真机验证记录（APP 自身收发）：

| 项目         | 发送                        | 结果                                                |
| ---------- | ------------------------- | ------------------------------------------------- |
| 三个模式(2,2)  | `2B 18 01 01 02 02 01 02` | ACK `2B 18 03 01 00`；0.8s 后回读 `2B 19` → 左=2 右=2 ✅ |
| 降噪+透传(3,3) | `2B 18 01 01 03 02 01 03` | 官方页面渲染「降噪✓ 关闭✗ 透传✓」 ✅                             |
| 恢复默认(2,2)  | 同上                        | 回读 2,2 ✅                                          |

APP 界面在「快捷操作 · 捏住轮换」里只保留**一个**按钮（三个模式 / 降噪+关闭 / 降噪+透传 / 关闭+透传），
连接与刷新时自动回读 `2B 19`。

> 真机实测：只有左耳写入生效，写入帧里右耳那一路写进去没有效果；而左耳改完后左右耳会自动同步成同一值，
> 与官方 APP 表现一致。因此界面不再提供左右耳两套按钮，写入时左右两个字段发同一个值。

## 实现过程中需要注意的地方（踩坑记录）

### 协议层

1. **`2B 04` 的应答不是状态**：`2B 04 02 01 00` 只是「写入确认」，早期拿它刷新界面，会把刚切好的降噪
   错误地刷回「关闭」。状态一律以 `2B 2A` 的应答为准。
2. **`2B 2A` 的字节顺序是 `[level][mode]`**：不是 `[mode][level]`。曾经为了兼容写成「取 ≤2 的那个字节」，
   结果 level=0（智能）时被误判成 mode=0（关闭）。现在固定：`value[0]=等级`、`value[1]=模式`。
3. **子命令 `2B xx 01 00` 不是纯查询**：实测全量扫描会把 ANC 从 `03 01` 改成 `00 00`。不要把它当「刷新」用，
   界面刷新只发 `2B 39` + `2B 2A`。
4. **`2B 04` 的载荷必须 6 字节**：早期按 5 字节 `2B 04 02 01 <mode>` 写，被耳机回 `02 01 00` 拒绝。
5. **长帧/短帧的判定依据**：官方日志 `ble_imp: writeDate ... length=N` 里 **N = 载荷长度 + 1**，
   不要把它当成整帧长度（整帧还要再加 5 字节帧头/CRC）。

### 连接层

6. **SPP 是独占的**：智慧空间（`com.hihonor.magichome`）后台服务会自动重连并占用通道，
   我们的 APP 会报 `read failed, socket might closed or timeout` / `Closed[19]`。
   使用前先 `adb shell am force-stop com.hihonor.magichome`，或直接在手机上划掉它。
7. **从后台切回前台必须重连**：被智慧空间抢过通道后，`BluetoothSocket` 已失效但对象还在。
   现在 `onResume()` 里判断 `isConnected()`，断了就自动重连并重新拉一次状态（电量 + 降噪）。
   首次进入用 `firstResume` 跳过，避免和 `onCreate` 的自动连接打架。
8. **UUID 要兜底**：主用 `00001101-0000-1000-8000-00805F9B34FB`，失败再试
   `82ff3820-8411-400c-b85a-55bdb32cf060`、`c9770a18-4c3d-453a-8aaf-d7ec7bbd2785`。
9. **耳机在充电盒内时任何客户端都改不了降噪**（官方 APP 也一样），这时写入会被耳机侧静默忽略。

### 调试与协议细节

10. **手机侧日志**：APP 里 `appendLog()` 同时打 `Log.i("EarbudCtl", ...)`，
    理论上可 `adb logcat -s EarbudCtl:I` 看全部收发帧。实测本台荣耀机 logcat 主缓冲区
    拿不到该 tag（输出恒为空），此时以界面 tv\_log 文本为准（见第 12 条）。
11. **观察官方 APP 的命令**：`adb logcat -c` → 在官方 APP 点一下 → `adb logcat -d | grep "5a2b"`。
    `Send data true, command = 5a2b04` 就是「服务 0x2B + 命令 0x04」，**但日志只有命令字和长度，没有字节**，
    这是分析 EQ/手势/LDAC 卡住的根本原因（详见 3.4）。
12. **UI 自动化点击**：官方页面会滚动/改版，旧坐标会点错。每次先 `adb shell uiautomator dump`
    取实时 `bounds` 再点，不要复用上一次的坐标。
13. **EQ 命令真相**：`01 39` 是属性写入通道（不是「设置同步查询」），EQ 真身是
    `01 39 service=3 prop=5`；`2B 6E` 在 USFY 固件上静默丢弃。详见 3.4。
14. **属性读取必须是两层嵌套 TLV**：`01 3A + TLV(1, TLV(2, TLV(3,service)+TLV(4,prop)+[05,00]))`。
    写成平铺 `01 3A + TLV(1,service) + TLV(2,prop)` 会被耳机回 `7F 04` 拒绝，
    这个坑排查了很久，因为 7F 看起来像「命令不支持」，实际是「结构不对」。
15. **开关类属性是 1=开、0=关**：service=6 的 LDAC/空间环绕声都按 `1=开 0=关` 写
    （真机帧与官方页面同刻比对确认）。注意 `service_text.json` 里的 `0/1` 是**文案索引**不是协议值，
    照它实现会得到完全相反的开关状态。
16. **枚举值要查官方配置**：官方配置 `service_text.json` 是 serviceIndex/propertyIndex/取值枚举的
    权威来源。光靠试写+读回会被骗（写 1 也能原样读回 1，但 1 不是合法枚举）。
17. **`7F` 不等于失败**：`01 39` 写属性后耳机固定回 `7F 04 00 01 86 A0`，
    但设置实际生效（官方 APP 同样无视这个 7F）。判断是否成功要靠 `01 3A` 读回或系统层副作用
    （如 LDAC 看 `dumpsys bluetooth_manager` 的 `codecName`）。
18. **改 LDAC 会重启耳机蓝牙**：A2DP 需要重新协商，SPP 会断开，且常出现连续两次掉线
    （重启主体 + 尾段）。APP 已实现断开后每 3s 自动重连、最多 10 次，重连成功后重新读回全部设置。
19. **`uiconfig.json` 决定「有哪些功能」**：它是官方 UI 的页面骨架，没有出现的 service/prop
    就不用去试（USFY 没有滑动页，`2B 1F` 也就必然无应答）。
20. **uiautomator dump 会剔除滚出屏幕的节点**：dump 里 "(not found)" 不代表控件不存在或文本为空——
    压缩 dump 只保留可视区内的节点。长页面（tv\_settings/tv\_log 在折叠线以下）必须先滚动到底再 dump，
    否则会误判成「UI 未更新」；tv\_log 文本可用 dump + 解析脚本提取验证。

## 已知限制

1. **降噪切换依赖耳机状态**：耳机在充电盒内时任何客户端（含官方 APP）都无法切换，
   取出后三档可任意直切。
2. **以回读为准**：设置后以 `2B 2A 01 02 <level> <mode>` 的**第二字节**（模式）判断；
   `2B 04` 的应答只是写入确认，不含状态。
3. 耳机需先用系统蓝牙配对。
4. SPP 通道需耳机固件支持 RFCOMM；连接被拒时确认耳机未连接到其它设备。
5. 同时只能有一个 SPP 客户端：使用本 APP 前需强停智慧空间，否则报 `Closed[19]`。
6. 固件升级后协议 tag 可能变化，届时需重新比对日志。
7. **充电状态未解析**：设备信息帧的 tag3 真机恒为 `64 64 00`，不是充电位；真实编码待耳机入盒充电时实测确认。
   在此之前界面一律不显示「充电中」，避免误报。
8. **重连后自动恢复播放**：通过系统媒体键（`KEYCODE_MEDIA_PLAY`）实现，依赖播放器仍保有媒体会话；
   部分 APP 在耳机重启期间会自行释放会话，此时按键可能无响应。
